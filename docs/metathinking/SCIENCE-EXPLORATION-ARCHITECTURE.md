# MindsEvo Learning — Science Exploration Architecture v0.1

## 1. 板块定位

**Science Exploration / 科学探索**

> 科学，不只是知道答案，而是学习如何寻找答案。  
> Science is not only knowing answers. It is learning how to find them.

Science Exploration 不是儿童科学百科，也不是把学校科学课程重新组织成在线选择题。

它以真实世界中的现象、变化、关系和问题作为载体，让儿童逐渐形成：

**观察世界 → 提出问题 → 作出预测 → 动手验证 → 判断证据 → 建立解释 → 根据新证据修正认识**

的基本科学认知方式。

整个板块遵循 MindsEvo 的总原则：

> Knowledge is the medium. Thinking is the goal.  
> 知识是载体，思维才是目标。

科学知识可以来自植物、动物、人体、物质、运动、光、声音、天气、宇宙和工程，但这些只作为 Context。一级架构按科学思维组织，不按知识章节组织。

### 1.1 Science Exploration 准入规则

一个任务即使使用植物、动物、天气、磁铁或太空等科学素材，也不能仅凭题材被归入 Science Exploration。

至少应要求儿童完成下列科学认知动作之一：

- 系统观察现象；
- 从现象中提出可探索问题；
- 在结果出现前作出预测；
- 改变或控制条件以进行验证；
- 判断哪些观察或数据构成相关证据；
- 用证据建立或修正解释。

主要依赖既有事实记忆的问题属于知识学习或百科测验，不是本板块的核心任务。

## 2. 六个核心科学元思维

Science Exploration 固定使用六个核心单元。

| 单元 | English | 核心问题 | 训练重点 |
|---|---|---|---|
| 观察 | Observation | 我发现了什么？ | 现象、特征、差异、变化和记录 |
| 提问 | Questioning | 我想知道什么？ | 从观察中发现未知，并形成可探索问题 |
| 预测 | Prediction | 我觉得会发生什么？ | 在结果出现前，根据线索或假设形成预期 |
| 实验 | Experimentation | 怎样才能知道？ | 操作、单一变量、公平比较和验证 |
| 证据 | Evidence | 我凭什么这样认为？ | 记录、测量、相关性、充分性和反例 |
| 解释 | Explanation | 这些现象说明什么？ | 把主张、证据与原因连接起来，并允许修正 |

六个单元既可独立训练，也形成循环：

**Observation → Questioning → Prediction → Experimentation → Evidence → Explanation**

Explanation 不是终点。解释会带来新的观察和问题，或者在新证据出现后被修正：

**Explanation → New Observation / New Question / Revision → New Exploration**

### 2.1 六个单元不是六门课程

同一个探索模板可以调用多个元思维。例如 Float or Sink 可以同时记录：

- Prediction：入水前的猜测；
- Experimentation：执行入水测试；
- Observation：看到浮起或沉下；
- Evidence：选择与结果相关的观察；
- Explanation：用材料或密度概念建立初步说明；
- Revision：实际结果与预测不同时修改原判断。

每个模板只上报实际发生并得到任务支持的 RootGene，不能因为属于 Science 模块就机械上报全部六个基因。

## 3. 八级认知成长阶梯

Science Exploration 保留 Learning Series 的 K1、K2、G1-G6 八级入口，但升级重点不是科学知识数量，而是儿童探索未知世界的方式。

| Level | 成长重点 | English | 典型能力 |
|---|---|---|---|
| K1 | 看见 | Notice | 发现明显现象、不同与变化 |
| K2 | 描述 | Describe | 用简单语言或表征记录观察结果 |
| G1 | 猜想 | Predict | 根据已知观察预测新结果 |
| G2 | 联系 | Relate | 发现条件与结果之间的关系，并提出可检验问题 |
| G3 | 验证 | Test | 设计简单公平实验，改变一个变量 |
| G4 | 证据 | Evidence | 使用多次观察或数据支持、削弱或推翻判断 |
| G5 | 解释 | Explain | 连接主张、证据和因果机制 |
| G6 | 修正 | Revise | 比较解释，质疑证据，并依据新证据修改模型 |

纵向成长主线为：

**看见 → 描述 → 猜想 → 联系 → 验证 → 证据 → 解释 → 修正**

### 3.1 成长主轴不等于能力独占

不应把六个科学元思维机械绑定到六个年级。

- K1 可以经历 Prediction → Test → Notice，只是预测不作为对错评分。
- K2 可以描述测试结果，并比较预测与观察。
- G1 可以根据过去观察预测新情境。
- G2 可以从关系中提出问题，并开始识别变量。
- G3-G6 逐步承担公平实验、证据充分性、因果解释和模型修正。

每个年级都可以运行完整或部分 Scientific Thinking Loop，差异在于儿童承担的认知责任、变量复杂度、证据数量和解释深度。

### 3.2 K1-G2 第一阶段责任

第一阶段聚焦 K1-G2，但不能停留在按常识选择答案。

**K1**
- 先预测，再亲自触发测试；
- 观察明显结果；
- 预测错误不判定为探索失败。

**K2**
- 描述发生了什么；
- 用现象语言而不是评价语言表达结果；
- 初步比较预测与观察。

**G1**
- 根据已经展示的观察或测试记录预测新情境；
- 说明预测所依据的可见线索；
- 开始区分线索与无关特征。

**G2**
- 识别可检验的问题；
- 发现条件与结果之间的联系；
- 在简单情境中识别要改变的变量、应保持不变的条件和需要观察的结果；
- 从少量结果中选择相关证据。

## 4. 科学探索场景库

科学场景是内容载体，不是一级思维架构。

### A. Life / 生命

植物、动物、人体、生长、环境和生态。

示例：
- 光照与植物变化；
- 动物运动和身体特征；
- 生长条件比较。

### B. Matter / 物质

固体、液体、气体、水、空气、材料、混合、溶解和状态变化。

示例：
- 浮与沉；
- 溶解与不溶解；
- 材料特征与磁性；
- 冰的融化。

### C. Motion & Force / 运动与力

推、拉、重力、摩擦、速度、斜坡和平衡。

示例：
- 斜坡高度和运动距离；
- 表面材料和摩擦；
- 推力大小和小车运动。

### D. Energy / 能量

光、声音、热、电和磁。

示例：
- 光源位置与影子；
- 距离与声音强弱；
- 热源与温度变化；
- 磁铁距离与吸引效果。

### E. Earth / 地球

天气、季节、水、岩石、土壤和自然变化。

示例：
- 降雨后的土壤变化；
- 天气记录；
- 水的流动和蒸发。

### F. Space / 宇宙

太阳、月亮、昼夜、星星和行星。

低龄阶段重点是观察和模型，不追求天文学知识量。

### G. Engineering / 工程与设计

材料、结构、桥梁、轮子、容器、简单机械和设计改进。

Engineering 连接 Science、Thinking 与 Making，但仍需区分：
- 为检验因果关系而改变变量，属于 Experimentation；
- 为达到设计目标而权衡方案，可能同时涉及 Strategy；
- 制作作品本身不能自动算作科学探索。

### 4.1 第一阶段 Context 范围

架构保留全部七个 Context，但首批标杆模板优先集中于：

- Matter；
- Motion & Force；
- Life；
- Energy。

Earth、Space 和 Engineering 保留结构，不为了表面覆盖而制造浅层知识题。

## 5. 四种基本任务形态

### 5.1 Observe

核心问题：

> What do you notice?  
> 你发现了什么？

儿童观察图片、动画、物体、过程或记录，识别：

- 特征；
- 变化；
- 差异；
- 共同点；
- 异常；
- 前后关系。

Observation 不是视觉搜索。视觉搜索重点是在干扰中找到目标；科学观察重点是记录现象本身的特征，为后续问题、预测或解释提供依据。

### 5.2 Predict

核心问题：

> What do you think will happen?  
> 你觉得会发生什么？

预测必须发生在结果显示之前，并尽可能记录预测依据。

预测错误不是失败。系统应保留原预测，进入测试并让儿童比较预测与结果。

### 5.3 Experiment

核心问题：

> How can we find out?  
> 怎样才能知道？

儿童通过操作对象、改变参数或选择测试设计来验证想法。

关键能力包括：

- 明确要改变的变量；
- 保持其他重要条件相同；
- 明确要观察或测量什么；
- 重复测试；
- 比较结果。

### 5.4 Explain

核心问题：

> What does the evidence tell us?  
> 证据说明了什么？

儿童使用现象、实验结果或简单数据：

- 选择相关证据；
- 区分证据和无关信息；
- 建立简单 Claim + Evidence + Reason；
- 在出现反例时修正解释。

## 6. Runtime 模式

### 6.1 Puzzle

**给出信息 → 思考 → 回答**

适合：

- 观察判断；
- 可检验问题识别；
- 基于已给证据的预测；
- 变量控制选择；
- 证据相关性或充分性判断；
- 解释构建。

Puzzle 可以判定答案，但不能用科学主题掩盖普通常识题。

### 6.2 Activity

**有明确任务 → 操作对象 → 达成科学目标**

示例：

- 移动光源观察影子；
- 调整斜坡；
- 把物体放入水中；
- 改变磁铁距离；
- 选择并固定实验条件。

Activity 记录操作过程，而不只记录最终答案。

### 6.3 Exploration

**自由改变变量 → 反复观察 → 自己寻找关系**

Exploration 不要求唯一固定操作路径，也不应只是选择题加动画。

系统重点记录：

- 儿童改变了什么；
- 哪些变量保持不变；
- 做了多少次测试；
- 观察到什么；
- 是否比较了结果；
- 是否形成或修正了判断。

Exploration 可以有完成条件，但不得把每个内部步骤上传为独立 Attempt。一个模板运行产生一个 Attempt，步骤保存在 trace/process 中。

## 7. 公共 Scientific Exploration Runtime

第一版公共运行机制固定为：

**Observe / Question → Predict → Test → Result → Evidence → Reflect / Explain / Revise**

模板可按年龄和目标省略部分阶段，但阶段语义必须保持一致。

### 7.1 Prediction

- 发生在测试之前；
- 记录预测内容；
- 可记录预测依据；
- 不立即显示红色错误；
- 不单独决定整个 Attempt 是否成功。

### 7.2 Test

- 必须由儿童触发，或由儿童选择测试方案；
- 记录 `action`；
- 改变变量时记录 `variable_changed`；
- 结果必须由活动模型产生，不由预测决定。

### 7.3 Observation / Result

- 清楚展示实际发生的现象；
- 记录 `observation` 与需要时的 `result`；
- 鼓励儿童先确认发生了什么，再进入解释。

### 7.4 Evidence

- 证据选项必须来自已经展示的观察、测试或数据；
- 区分 relevant、irrelevant、insufficient 和 conflicting evidence；
- 不得把一般知识陈述伪装成当前实验的证据。

### 7.5 Reflection / Revision

当预测与结果不一致时，系统应使用中性语言：

- “结果和你的预测一样吗？”
- “你现在怎么想？”
- “哪一条观察让你改变了想法？”

Revision 应记录原判断、新判断和触发修正的证据。

## 8. Science Attempt 与过程数据

Puzzle 仍可记录 correct / incorrect，但 Science 总体不能只用 Accuracy 描述成长。

一个 Science Attempt 可以包含：

```text
templateId
variantId
levelId
contextDomain
runtimeMode
observation
question
prediction
predictionBasis
actions[]
variablesChanged[]
controlledVariables[]
results[]
evidenceSelected[]
explanation
revision
process
trace
```

### 8.1 公共事件词汇

第一阶段统一使用：

- `observation`
- `question`
- `prediction`
- `action`
- `variable_changed`
- `result`
- `evidence_selected`
- `explanation`
- `revision`

### 8.2 汇总原则

- 完整事件保存在 trace/context；
- mastery/analytics 使用有限、扁平的 process summary；
- 一个 Exploration 模板只产生一个 Attempt；
- Puzzle 与 Exploration 的时间不可直接混算；
- Prediction accuracy 不能等同于 scientific-thinking quality；
- 不将六个能力压成一个无上下文的“科学分数”。

### 8.3 推荐成长指标

- Observation completeness；
- Testable-question recognition；
- Prediction completion；
- Prediction-basis use；
- Experiment completion；
- Target-variable isolation；
- Controlled-condition consistency；
- Repeated-test behavior；
- Evidence relevance；
- Evidence sufficiency awareness；
- Explanation quality；
- Revision after conflicting evidence。

## 9. 模板架构

Science Exploration 使用：

**Thinking Unit → Level → Context → Template → Variant → Attempt**

示例：

```text
Science
 └── Prediction
      └── G1
           └── Motion & Force
                └── Ramp Prediction
                     ├── Variant 001
                     ├── Variant 002
                     └── ...
```

### 9.1 Template

Template 定义稳定的思维任务，包括：

- 主要和次要 Scientific Thinking Unit；
- 年级；
- Context；
- Runtime；
- 任务阶段；
- 可改变变量；
- 受控变量；
- 观察结果；
- 证据结构；
- 解释或修正要求；
- RootGene；
- 难度轴。

### 9.2 Variant

Variant 可以改变：

- 对象；
- 数值；
- 材料；
- 初始条件；
- 变量值；
- 场景外观；
- 证据顺序；
- 无关信息；
- 反例。

Variant 不能改变模板训练的核心科学认知动作。

### 9.3 Attempt

Attempt 表示一次完整思维经历，而不是一个静态题目的答案副本。

## 10. 难度架构

科学难度不能只靠增加对象数量、增加文字或缩短时间。

公共难度轴包括：

- `object_complexity`
- `variable_complexity`
- `inference_complexity`
- `language_complexity`
- `transfer_complexity`
- `evidence_complexity`
- `control_complexity`
- `revision_demand`

典型进阶：

### Object Complexity
`concrete → represented → symbolic → abstract`

### Variable Complexity
`single_observed → single_changed → controlled_single → interacting_variables`

### Evidence Complexity
`single_result → repeated_results → mixed_results → conflicting_evidence`

### Explanation Complexity
`describe → relate → claim_evidence → causal_model → revised_model`

### Revision Demand
`none → compare_prediction → revise_claim → compare_models`

## 11. 与其他 MindsEvo 家族的边界

### Pattern Hunter

- Pattern：发现已经展示的数据或序列中的结构；
- Science Prediction：根据对原因的假设，在测试前预测尚未出现的结果。

仅延续一个可见序列不自动属于科学预测。

### Memory Guardian

- Memory：信息消失后保持、提取或重组；
- Science：利用观察、实验和证据形成可检验认识。

记住实验结果可以支持 Science，但如果主要难点是隐藏后的回忆，主能力仍属于 Memory。

### Strategy Master

- Strategy：在多个可行方案中权衡取舍并安排行动；
- Experimentation：为了检验因果假设而隔离和控制变量。

一般行动规划不能自动标记为实验设计。

### Mathematics

数学训练在抽象关系中思考，科学训练面对未知世界寻找答案。

同一探索可以同时调用数学 RootGene，例如：

- 比较两株高度；
- 读取数量；
- 发现变化趋势；
- 建立图表模型。

后台应按实际行为进行 M:N RootGene 上报，而不是强行把任务归为单一学科。

### Knowledge Learning

- “哪种动物会飞？”如果只依赖已有常识，主要是知识题；
- 给出身体结构、过去测试或可操作实验，再要求儿童预测和验证，才形成科学思维任务。

## 12. 第一阶段标杆模板

第一阶段先建立少量高质量模板，验证架构和 Runtime，不急于扩大知识题数量。

### 12.1 Float or Sink

Context：Matter  
Runtime：Exploration

验证：

**Predict → Test → Observe → Evidence → Explain → Revise**

改进要求：

- 预测错误不作为探索失败；
- 测试由儿童触发；
- 实际结果单独记录；
- Evidence 必须来自刚才的测试；
- 变量变化必须真正影响结果或被明确说明为无效测试，不能只记录点击。

### 12.2 Ramp Lab

Context：Motion & Force  
Runtime：Activity / Exploration

验证：

- 改变斜坡高度；
- 保持球和表面相同；
- 预测运动距离；
- 重复测试；
- 比较结果；
- 初步形成“斜坡高度与运动结果”的关系。

### 12.3 Shadow Changes

Context：Energy  
Runtime：Activity

验证 Observation：

- 移动光源；
- 观察影子的方向、位置和大小；
- 描述发生了什么；
- 区分观察结果和原因解释。

### 12.4 Which Question Can We Test?

Context：跨 Life / Matter / Motion / Energy  
Runtime：Puzzle

验证 Questioning：

- 区分可由当前场景观察或实验回答的问题；
- 排除偏好、价值判断、过于宽泛和缺少可操作变量的问题；
- G2 开始识别问题中的变量和结果。

### 12.5 What Should We Change?

Context：Life / Engineering  
Runtime：Puzzle / Activity

验证 Experimentation：

- 明确想检验的想法；
- 选择改变的变量；
- 选择保持相同的条件；
- 选择要观察或测量的结果。

### 12.6 Which Result Is Evidence?

Context：Matter / Motion  
Runtime：Puzzle

验证 Evidence：

- 选择相关观察；
- 排除无关特征；
- 逐步加入单次结果、多次结果和冲突结果；
- 避免把结论本身当成证据。

### 12.7 Build an Explanation

Context：Motion / Life  
Runtime：Puzzle / Activity

验证 Explanation：

**Claim + Evidence + Simple Reason**

解释的正确性必须依赖题目提供的观察和证据，而不是仅靠背诵事实。

## 13. 当前实现评估

当前 `learning/science` 已经具备有价值的基础：

- Puzzle 管线；
- Explore Runtime；
- Template → Variant → Attempt；
- K1-G2 入口；
- 六个 Science RootGene；
- `observation`、`prediction`、`action`、`variable_changed`、`evidence_selected`、`explanation` 和 `revision` 事件；
- 完整 trace 与扁平 process summary 分离；
- 一个 Explore 模板只产生一个 Attempt。

但当前实现仍属于 architecture-scaffold MVP，主要问题包括：

- 许多 Puzzle 直接依赖儿童已有常识；
- 部分预测没有后续测试；
- `variable_changed` 目前可能只记录选择，而没有重新运行并产生可比较结果；
- Evidence 选择与实际观察的绑定仍弱；
- Explore 的最终完成状态过度依赖选中预设解释；
- 预测正确率仍容易被当成成功标准；
- K1 Explore 模板同时认领全部六个 RootGene，尚未根据实际阶段精确归因；
- Activity 尚未形成独立公共 Runtime；
- 现有 K1-G2 模板数量和认知形态不足以验证完整架构。

因此下一轮开发应优先增强公共 Runtime 和模板认知深度，而不是继续增加类似的二选一常识题。

---

## 14. 实施路线

### Phase 1：架构与合同

1. 以本文档固定 Science Exploration 定位、六个元思维、八级成长、七个 Context 和三种 Runtime。
2. 更新 `metadata/metathinking/science.json`，使其引用并遵循本文档。
3. 明确成长主轴不等于能力独占。
4. 为 Template 增加 thinking unit、stages、variables、evidence 和 revision 等结构。
5. 固化 Science Attempt、trace 和 process summary 合同。

### Phase 2：公共 Runtime

6. 将 Explore Runtime 从现象专用分支改为阶段驱动：
   `predict → test → observe/result → evidence → reflect/explain/revise`。
7. 让变量变化真正触发新的测试结果，而不是只记录点击。
8. 增加 Prediction 与 Observation 的显式对照。
9. 增加中性 Reflection 和 Revision。
10. 将 Explore 成功标准从“最后选中预设答案”改成“完成必要科学过程”，同时独立记录解释质量。
11. 建立 Activity Runtime，用于有明确任务的可操作实验。

### Phase 3：参考模板

12. 重构 Float or Sink，作为公共 Scientific Thinking Loop 的参考实现。
13. 实现 Ramp Lab，验证变量操作、重复测试和结果比较。
14. 实现 Shadow Changes，验证 Activity 和 Observation。
15. 升级 Which Question Can We Test，验证 G2 Questioning。
16. 实现 What Should We Change，验证变量控制。
17. 实现 Evidence 和 Explanation 标杆模板。

### Phase 4：K1-G2 模板矩阵

18. 每个核心元思维先建立 3-5 个高质量模板。
19. 优先覆盖 Matter、Motion & Force、Life、Energy。
20. 检查每个模板是否依赖题目中提供的现象、测试或证据。
21. 检查所有 runtime 是否记录实际思维过程。
22. 完成 K1-G2 手工体验与内容审查后，再扩展 G3-G6。

## 15. 第一阶段完成标准

Science Exploration 第一阶段不能只按题目数量验收。至少应满足：

- 六个 Scientific Thinking Unit 都有可运行参考模板；
- K1-G2 均不只包含常识选择题；
- 至少一个完整 Prediction → Test → Evidence → Reflection 闭环；
- 至少一个真正改变变量并重新产生结果的 Exploration；
- 至少一个明确控制变量的 Experimentation 任务；
- 至少一个基于多条结果判断证据的任务；
- 预测错误不会直接导致探索失败；
- Revision 可以被真实触发并记录；
- Puzzle、Activity、Exploration 的语义和统计口径清楚分离；
- RootGene 只按实际任务行为上报；
- Science Attempt 可以形成过程型 Thinking Growth Profile；
- 不依赖科学百科式题库来制造难度。

当这些标准稳定以后，Science Exploration 才从 scaffold 进入可扩展的 MVP。
