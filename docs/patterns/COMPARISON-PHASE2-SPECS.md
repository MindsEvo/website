## 1. 本阶段所有规格共用的规则

### 1.1 证据原则（comparison.json → designModel.commonSenseRule）
答案必须能从题面画出的证据推出。验收方法：**把所有物体换成同一个中性图标后，题目仍然可解**。W、S、Z1、Z2、Z4、Z5 都必须满足。

**唯一例外是 Z3**，因为它训练的是抑制感知干扰，不是常识本身。例外的条件是：
（a）所用的真实大小关系是 5 岁儿童显然知道的（等级差 ≥ 4，见 Z3）；
（b）难度完全来自与之冲突的画面线索：去掉冲突线索后，题目必须变得非常简单。

### 1.2 身份中性
- 被比较的对象必须**外观完全相同**：同一个图标、同样大小、同样颜色。区分它们的只有槽位字母 A / B / C。
- 槽位标记一律用中性色 `SLOT_NEUTRAL`。不得把 length / height 的彩色槽位扩展到这些类型，因为颜色本身会成为区分线索。
- 选项卡片只画槽位字母（沿用 `_optPointer`），不重画任何被比较的属性。

### 1.3 选项与「一样」
- 两个对象的判断题固定 3 个选项：`left` / `right` / `same`。`same` 渲染为「一样重 / 一样快 / 一样大」的文字卡，没有槽位字母。
- 三个对象的选出题固定 3 个选项：`A` / `B` / `C`。不设「一样」，构造时保证不会出现并列。
- 每条规格写明 `same` 为正确答案的目标比例，由生成器按比例抽样，不靠碰运气。

### 1.4 答案均衡（test.html 对每个模板抽 200 次统计）
- 左 / 右（或 A / B / C）作为正确答案的比例，各自落在均分值 ±12% 之内；
- 提问方向（重 / 轻、快 / 慢、大 / 小）各占 40–60%；
- `same` 为正确答案的比例落在目标值 ±8% 之内。

### 1.5 题面多样性
- 每个模板 200 次抽样中，不同题面签名（`CmpEngine.variantSignature`）至少 24 个。低于这个数，近期题面记忆（5 次）就挡不住重复。
- 各图标池的最小规模在各规格里写明。

### 1.6 error_type 词表（puzzle 首次使用）
每道题带 `optionTypes`：`{ left|right|same|A|B|C → error_type }`。`onAnswer` 把所选项的 error_type 写进 attempt 的 `process.errorType`。取值只限下表，不得新增：

| error_type | 含义 |
|---|---|
| `none` | 正确 |
| `polarity_confusion` | 问的是一个方向，选了另一个方向（问更轻却选了更重） |
| `perception` | 被表面线索带走：画得大、外框大、边长、跑道位置 |
| `false_equal` | 两者不等，却选了「一样」 |
| `missed_equal` | 两者相等，却选了其中一边 |
| `middle_item` | 三选一时选了中间那个（既不是最大也不是最小） |
| `inverse_relation` | 反比关系用反了：同样路程，把用时多的当成快的 |

### 1.7 上线时要同步的元数据
- 本阶段完成后，`comparison.json` 中以下各格的 `status` 改为 `implemented`：`mediated × judge / select`、`transitive × judge / select`、`interference × judge`；`direct × select` 改为 `implemented`。
- `typeTree.mediated / transitive / interference` 改为 `partial`，并补上 `implementedBy`。
- `carriers.area.status` 改为 `active`。
- levelMap 各行按上线情况，把结构和任务从 `planned*` 移入 `primary*`。
- `metadata/validate.js` 的 S4 / S5 / S8 会逐条核对，不一致会报 FAIL。

## 2. 轻重：天平证据题

共用画面：天平用 SVG 画，包括支点三角、横梁、两个托盘。托盘上的物体是**同一个「神秘物件」图标**，每题从池中抽一个，池至少 8 个：📦 🎁 🧺 🪣 🥫 🫙 🧳 🗃️。物件下方挂槽位字母。
- 较重的一侧托盘下沉。倾角**固定为 14°**，不随轻重差变化，免得「倾得多」成为额外线索；
- 两边相等时横梁水平，倾角为 0°。

### W1 · 天平看轻重（K2）
- 三维：`structure=mediated` · `carrier=weight` · `task=judge` · 所在格 `mediated×judge`（起始年级 K2，本题 K2，合规）· runtime `puzzle` · 基因 `RG.LOGIC.COMPARISON.BASIC`
- ability_tag：`comparison.mediated.judge.weight`
- 训练目标：两个外观一样的盒子，只能看天平判断哪个重、哪个轻，或者一样重。
- 允许变量：物件图标（池抽取）；重的一侧在左或右；提问方向；是否相等。
- 禁止变量：两个物件外观的任何差别；倾角大小；物件的名称或文字。
- 出题规则：先抽关系 `rel ∈ {left, right, same}`，`same` 占 25%，其余两种各占一半；再抽提问方向（重 / 轻各 50%）。
- 答案：`rel=same` 时答案为 `same`；否则问「重」答下沉的一侧，问「轻」答上翘的一侧。
- optionTypes：正确项为 `none`；选了另一侧为 `polarity_confusion`；不等时选 `same` 为 `false_equal`；相等时选了一侧为 `missed_equal`。
- 正例：📦A 下沉、📦B 上翘，问「哪个更轻？」，答 `right`。
- 反例：A 画成 🧳、B 画成 📦（外观不同，拒绝）；轻重差大就倾得更多（拒绝）。
- 自检：由 `rel` 和倾角独立推出答案；两侧图标相同；倾角只能是 0° 或 ±14°；按 §1.4 统计比例；签名数 ≥ 24。

### W2 · 三个盒子，谁最重（G1）
- 三维：`mediated` · `weight` · `select` · 所在格 `mediated×select`（起始年级 G1，本题 G1）· `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：综合**三架**天平的结果，找出最重（或最轻）的那一个。
- 画面：三架小天平排成一行，分别是 A–B、A–C、B–C。**每一对都给出**，所以不需要传递推理。每个盒子恰好出现在两架天平上，出现次数不会泄露答案。
- 允许变量：隐藏重量（1、2、3 的一个排列）；三架天平的左右顺序；每架天平里谁在左、谁在右；提问方向（最重 / 最轻各 50%）。
- 禁止变量：并列；A、B、C 三个盒子外观不同；三架天平固定按 A–B、A–C、B–C 的次序排列（必须打乱）。
- 答案：最重（或最轻）的那个字母。答案落在 A、B、C 上的机会均等。
- optionTypes：正确项为 `none`；选了另一个极端为 `polarity_confusion`；选了中间那个为 `middle_item`。
- 反例：只给两架天平，而且答案恰好是出现两次的那个盒子（出现次数泄露答案，拒绝）。
- 自检：从三架天平的倾向独立推出排序，与隐藏重量一致；A、B、C 各自作为答案的比例在 33% ± 12% 之内。

### W3 · 链式天平（G2）
- 三维：`transitive` · `weight` · `select` · 所在格 `transitive×select`（起始年级 G2）· `puzzle` · 基因 `RG.LOGIC.COMPARISON.BASIC` 与 `RG.LOGIC.REASONING.BASIC`
- 训练目标：只有两架天平，最重的和最轻的**从不同时出现在一架天平上**，只能靠传递关系推出答案。
- 画面：两架天平，一架比较 X 与 M，另一架比较 M 与 Y。M 是中间那个。
- **唯一性条件**：M 必须在一架天平里是重的一方，在另一架里是轻的一方，这样三个盒子才构成一条链。若 M 在两架天平里都是重的（或都是轻的），最轻（或最重）的那个就推不出来，这种题禁止入库。
- 允许变量：哪个字母做 M；两架天平的上下顺序；每架天平的左右摆放；提问方向。
- 禁止变量：M 永远排在两架天平的同一侧；答案永远在第一架天平上。
- 出现次数：M 出现两次，X、Y 各出现一次。出现一次的有两个候选，所以次数本身不泄露答案；干扰项 `middle_item` 恰好能暴露「挑出现次数最多的」这种错误策略。
- optionTypes：正确项为 `none`；选了另一个极端为 `polarity_confusion`；选了 M 为 `middle_item`。
- 自检：对每道题独立检查链条件；从两架天平推出全序，与答案一致。

### W4 · 天平替换（G2）
- 三维：`transitive` · `weight` · `judge` · 所在格 `transitive×judge`（起始年级 G2）· `puzzle` · 基因 `RG.LOGIC.COMPARISON.BASIC` 与 `RG.LOGIC.REASONING.BASIC`
- 训练目标：看懂「k 个小球和 1 个方块一样重」，据此判断 m 个方块和 n 个小球哪边重。
- 画面：
  - 上方是一架**水平**的天平，一边放 k 个红色小球，一边放 1 个蓝色方块，都用 SVG 几何图形，不用水果之类的真实物体，避免常识介入；
  - 下方是两个托盘，**不画横梁**，一边放 m 个方块，一边放 n 个小球，中间一个「?」。
  - 不画横梁是刻意的：水平的横梁会被读成「一样重」，倾斜的横梁会直接给出答案。
- 参数范围：k ∈ {2, 3}；m ∈ {1, 2}；n ∈ [1, 7]。一个方块等于 k 个小球，比较的是 m×k 与 n。`m×k = n` 的比例占 25%。方块托盘在左或右各占一半。
- 禁止变量：`n = m`（数量相同会诱导孩子只数个数，不做替换，这正是要训练去克服的错误，应该通过干扰项暴露，而不是回避）。当 `m×k ≠ n` 时，至少一半的题要满足「个数多的一边反而轻」，即 n > m 且 n < m×k。
- 选项：方块那一侧 / 小球那一侧 / 一样重。
- optionTypes：正确项为 `none`；选了个数多的一边但错了，记为 `perception`；不等时选「一样重」为 `false_equal`；相等时选了一边为 `missed_equal`。
- 正例：k=3，m=1，n=2。一个方块等于 3 个小球，大于 2 个小球，所以方块那边重；而且小球个数更多，属于冲突题。
- 自检：从 k、m、n 推出答案；统计冲突题的比例；统计相等题的比例。

## 3. 快慢：赛跑证据题

共用画面：2 到 3 条横向跑道，起跑线对齐，终点插一面旗。每条跑道上是**同一种**选手图标，每题从池中抽一个，池至少 8 个：🐢 🐇 🐌 🦔 🐿️ 🐤 🐶 🐱。每条跑道画一个秒表，旁边写秒数，例如「⏱ 5 秒」。
- 不画速度线、尘土这类暗示快慢的装饰；
- 选手的朝向一致。

### S1 · 同样时间，谁跑得远（K2）
- 三维：`mediated` · `speed` · `judge` · 所在格 `mediated×judge`（起始年级 K2）· `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：两个选手跑了**一样长的时间**，跑得远的那个更快。
- 画面：两条跑道，两个秒表的秒数相同（从 3–9 秒中抽取，K2 可以用数字）。选手停在不同位置，位置差至少是跑道长度的 25%。
- `same` 的情况：两个选手停在同一位置，占 20%。
- optionTypes：正确项为 `none`；选了跑得近的为 `polarity_confusion`；另加 `false_equal` / `missed_equal`。
- 禁止变量：两个秒表秒数不同；两条跑道长度不同；选手图标不同。
- 自检：由位置和提问方向推出答案；两个秒表秒数一致；位置差 ≥ 25%（相等题除外）。

### S2 · 三个选手，谁最快（G1）
- 三维：`mediated` · `speed` · `select` · 所在格 `mediated×select`（起始年级 G1）· `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 画面：三条跑道，秒表秒数相同。三个选手的位置互不相同，相邻两者之差至少是跑道长度的 18%。
- 提问：最快 / 最慢各占 50%。
- optionTypes：正确项为 `none`；选了另一个极端为 `polarity_confusion`；选了中间那个为 `middle_item`。
- 自检：答案是跑得最远（或最近）的那个；A、B、C 作为答案的比例均衡。

### S3 · 先看清哪个量一样（G2）
- 三维：`mediated` · `speed` · `judge` · 所在格 `mediated×judge` · `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：先分清**哪个量相同**，再决定用哪条规则。
  - 变体 A（50%）：时间相同，路程不同。跑得远的快。
  - 变体 B（50%）：路程相同，两个选手都站在终点旗下，秒表秒数不同。**用时少的快**。
- 两种变体的问题文字完全相同，都是「谁跑得更快？」或「谁跑得更慢？」。孩子必须自己看出哪个量相同，这正是本题的训练点。
- 参数：变体 B 的秒数在 [5, 60] 之内，两者之比至少 1.25（不超出 G2 的 100 以内范围）。`same` 占 15%：变体 A 中位置相同，或变体 B 中秒数相同。
- 禁止变量：路程和时间同时不同（那需要求速度，属于 G3 以后）；变体 B 中选手的位置有任何差别。
- optionTypes：
  - 变体 B 中，问「快」却选了秒数大的，或问「慢」却选了秒数小的，记为 `inverse_relation`；
  - 变体 A 中方向选反记为 `polarity_confusion`；
  - 另加 `false_equal` / `missed_equal`。
- 正例（变体 B）：A 用时 8 秒，B 用时 12 秒，问「谁跑得更快？」，答 A；选 B 记为 `inverse_relation`。
- 自检：
  - 变体标记与画面一致：变体 A 秒数相同，变体 B 位置相同；
  - 分变体推出答案；
  - 两种变体各占 50% ± 10%；
  - 变体 B 中「秒数大的是正确答案」（即问「慢」的情况）占 40–60%，保证不能靠「总选小数字」过关。

## 4. 大小：按年级重做

### Z1 · 同一物体，哪个大（K1）
- 三维：`direct` · `size` · `judge` · 所在格 `direct×judge`（起始年级 K1）· `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：只有尺寸一个变量的直接比较。它仍然是感知题；改动的要点是去掉「物种不同」这个会带出常识的变量。这与现有的高度题同一原则。
- 画面：**同一个图标**画两次，尺寸不同，放在同一条底线上。
- 参数：较小者的线性尺寸不超过较大者的 70%（K1 要一眼可辨）；绝对尺寸在 36–88 px 之间。
- 图标池：两个模板各用一池，每池至少 12 个图标。size-001 用动物，size-002 用日常物品，如 🍎 ⚽ 🎈 🧸 🚗 ⭐ 🌸 🍪 🎁 🪁 🧁 🥕。
- 选项：`left` / `right`，**不设「一样」**。K1 先建立「大小不同」的判断，`same` 由等同判断的题型承担。
- 提问：大 / 小各占 50%。
- 选项卡片只画槽位字母，不画物体名称。两侧是同一个物体，写名称没有意义。
- optionTypes：正确项为 `none`；选反为 `polarity_confusion`。
- 自检：两侧图标相同；尺寸比 ≤ 0.70；每池至少 12 个图标；签名数 ≥ 24。

### Z2 · 三个里面找最大（K1）
- 三维：`direct` · `size` · `select` · 所在格 `direct×select`（起始年级 K1）· `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：从三个中选出最大（或最小）的。猜对率从 50% 降到 33%，也是后面「找极值」「排序」的基础。
- 画面：同一图标画三次，线性尺寸比例约为 1 : 0.78 : 0.6，相邻两者之比 ≤ 0.8。三者的左右顺序随机，**最大的不得固定在中间或两端**。
- 提问：最大 / 最小各占 50%。
- optionTypes：正确项为 `none`；选了另一个极端为 `polarity_confusion`；选了中间尺寸为 `middle_item`。
- 自检：相邻尺寸比 ≤ 0.8；A、B、C 作为答案各占 33% ± 12%。

### Z3 · 画得大，还是真的大（K2）
- 三维：`interference` · `size` · `judge` · 所在格 `interference×judge`（起始年级 K2）· `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：抑制画面线索，并听清问的是哪一种大小。这是 §1.1 的唯一例外，满足那里的两个条件。
- 物体池：至少 14 个动物或物体，每个带真实大小等级 1–10。每题抽两个，**等级差 ≥ 4**，例如大象 10 对老鼠 1、鲸 10 对小鸟 2、汽车 8 对苹果 2。
- 画面：两个物体画在同一底线上，画出的尺寸比 ≥ 1.8，画面上的大小一眼可辨。
  - **冲突题（60%）**：真实较大的那个画得小；
  - **一致题（40%）**：画面大小与真实大小一致。
  - 必须有一致题，否则孩子会学会「总选画得小的」。
- 提问有两种框架：
  - 「哪个**真的**更大？」占 70%；
  - 「图上哪个**画得**更大？」占 30%。
  - 关键字加粗，语音朗读时重读。
- 选项：`left` / `right`。选项卡片可以显示物体名称：名称要表达的正是真实大小，而真实大小就是本题要问的内容。
- optionTypes：
  - 在冲突题上问「真的」却选了画得大的，记为 `perception`；
  - 问「画得」却选了真实大的，同样记为 `perception`（这是被常识带走，属于跟错了线索，两种情况合用一个标签）；
  - 其余选反记为 `polarity_confusion`。
- 反例：等级差 < 4（例如狗和羊，孩子未必知道谁大，拒绝）；冲突题中画面尺寸比 < 1.8（冲突不明显，训练不到抑制，拒绝）。
- 自检：冲突题占 60% ± 10%；两种框架占 70/30 ± 10%；按框架推出答案。

### Z4 · 数方格比面积（G1）
- 三维：`mediated` · `area` · `judge` · 所在格 `mediated×judge`；`area` 载体起始年级 G1 · `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：形状不同，不能靠目测，要借助单位方格计数来比较。对应一年级「认识图形」与计数。
- 画面：两个由单位方格拼成的图形（多格骨牌），各画在自己的浅色网格上，方格边线清晰可数。
- 构造：从一个方格出发，随机向相邻格生长，得到连通图形，边界框不超过 5×4。每个图形 4–12 格，两者相差 1–3 格；`same` 占 20%。
- **反线索条件**：在不相等的题中，至少一半要满足「方格更多的那个，边界框面积反而更小或相等」，免得「看着大的就是大」总能过关。
- 选项：`left` / `right` / `same`（一样大）。
- optionTypes：正确项为 `none`；选了边界框大但方格少的，记为 `perception`；另加 `false_equal` / `missed_equal`。
- 自检：独立数出两边方格数，推出答案；检查连通性；统计反线索比例 ≥ 50%；两个图形不得全等（全等时一眼就知道一样大，训练不到计数）。

### Z5 · 细长的不一定大（G2）
- 三维：`interference` · `area` · `judge` · 所在格 `interference×judge`（起始年级 K2）；`area` 载体起始年级 G1 · `puzzle` · `RG.LOGIC.COMPARISON.BASIC`
- 训练目标：抵抗「长的就大」这条边长线索。可以数格子，也可以用二年级学的乘法口诀「几行几列」。
- 画面：两个画了网格线的长方形，a×b 与 c×d，边长 1–9，面积 ≤ 36。
- **冲突条件**：在不相等的题中，至少 60% 要满足「最长边更长的那个，面积反而更小」，例如 1×9（面积 9）对 3×4（面积 12）。
- 相等题占 25%，从面积相等、形状不同的组合中抽，例如 2×6 与 3×4、1×9 与 3×3、2×8 与 4×4、3×8 与 4×6、4×9 与 6×6。
- 选项：`left` / `right` / `same`（一样大）。
- optionTypes：选了更长但更小的，记为 `perception`；另加 `false_equal` / `missed_equal`；方向选反记为 `polarity_confusion`。
- 参数写法：模板 params 写 `maxSide: 9`、`maxArea: 36`，由 S8 的数范围检查核对（在 G2 的 1–100 之内）。
- 自检：由 a×b 和 c×d 推出答案；统计冲突比例 ≥ 60%；统计相等比例；两个长方形不得全等，也不得只是同一个长方形旋转 90°。
