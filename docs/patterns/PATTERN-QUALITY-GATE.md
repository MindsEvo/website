# Pattern 模块出题与质量门禁规范

## 版本

- v1.1.0 (2026-08-12) — 新增 §8 Interaction（拖放活动）门禁
- v1.0.0 (2026-07-03)
- 适用范围：所有 Pattern 系列（Number / Color / Visual / Temporal / Motion / Size）
  与 Learning 系列的 Puzzle / Interaction 活动

## 1. 目标

本规范用于保证 Pattern 模块在扩展时：

1. 题型边界清晰，可解释且可复核。
2. 干扰项设计一致，错误归因稳定。
3. 数据记录结构统一，可横向比较。
4. 不因题目漂移导致能力标签失真。

## 2. 题型规格必须先行（先规格后实现）

每个新题型上线前必须有题型规格单（见附录 A），至少覆盖：

1. pattern_type
2. ability_tag
3. 允许变量
4. 禁止变量
5. 序列长度
6. 干扰项模板
7. error_type 映射规则
8. 边界策略
9. 示例题与反例题

未完成规格单，不得进入开发。

## 3. 通用质量门禁

### 3.1 单变量原则

单题只允许一个主变量发生变化。若同时变化多个变量，必须拆成独立题型。

### 3.2 可辨识性原则

关键差异必须肉眼可分辨，不允许边界模糊导致多解。

### 3.3 无歧义原则

题目应保证唯一最优答案，且干扰项有明确错误语义。

### 3.4 边界显式原则

越界规则（如最大值后行为）必须在规格单明示，不得隐式处理。

### 3.5 可归因原则

每个错误选项必须可映射到明确 error_type。

## 4. 干扰项与错误类型规范

每题 4 个选项建议结构：

1. correct
2. pattern_misread（规律误读）
3. adjacent_item（相邻项误判）
4. random 或 extreme_out_of_range

循环题可替换为 cycle_misalign。

error_type 命名必须统一使用小写蛇形（snake_case），禁止同义重复命名。

## 5. 数据记录规范

推荐单题记录字段：

```json
{
  "module": "size_pattern",
  "pattern_type": "grow",
  "level": 1,
  "correct": true,
  "time_ms": 3500,
  "error_type": "none"
}
```

要求：

1. module 与 pattern_type 必填。
2. time_ms 使用毫秒整数。
3. error_type 来自预定义集合。
4. ability_tag 映射规则在模块级文档中固定。

## 6. Size Pattern 专项边界（首版固定）

1. 只做纯视觉大小感知。
2. 禁止数字、单位、百分比、倍数计算。
3. 固定离散档位（3-4 档）。
4. 统一基线对齐，避免位置线索干扰。
5. 同题固定同一图形，仅改变整体大小。
6. 首版不做动画，不做二维长宽比变化。

## 7. 上线前最小测试集

### 7.1 出题校验

1. 100 道随机题无越界。
2. 所有题 answer 均包含在 options 内。
3. 所有 options 可映射到已定义 optionTypes。
4. 无重复选项、无空值选项。

> 第 2–4 条只适用于选择题。拖放类活动没有 options，**不得**套用这三条
> （否则合法活动会被判为不合格），改按 §8 校验。

### 7.2 渲染校验

1. 问号占位统一为 '?'.
2. 序列与选项在移动端可完整显示。
3. 基线对齐策略在各屏宽下一致。

### 7.3 统计校验

1. 正误计数正确。
2. error_type 统计与作答结果一致。
3. 历史记录写入与读取正常。

## 8. Interaction（拖放活动）门禁

参考实现：`docs/patterns/COMPARISON-INTERACTION-IMPLEMENTATION.md`

### 8.1 结构合法性（替代"answer 在 options 内"）

拖放活动的"正确答案"是一个映射或顺序，不是一个选项。上线前必须逐 mode 校验：

| mode | 必须成立 |
|------|----------|
| sort | 目标顺序与元素一一对应、严格单调、相邻差值 ≥ 规格单声明的最小可辨识差 |
| match | 左右等量、每个待配对项**恰好**有一个正确目标、映射一对一 |
| group | 物品总数 = 分组数 × 每组数、每组期望数量正确、组标识合法 |
| fit | 恰好一个明确的不合格项、正确项确实可用、正确项是最优解（最小的可用项） |

通用要求：元素 id 唯一、渲染所需字段（尺寸/颜色/emoji）齐全、
每次生成的布局指纹去重率 ≥ 50%。

### 8.2 唯一最优解原则

§3.3 无歧义原则在拖放活动里的含义是：**允许多个可行解，但必须有唯一最优解，
且非最优解必须给出区别于错误的反馈。**

以 Fit（搭桥）为例：任何长度足够的木板都能过河，所以都算完成；
但「刚好」与「过长」必须给不同文案（`optimal` 字段区分），
绝不允许把可行解报成失败，更不允许用错误的原因描述（如把过长的板说成"太短"）。

### 8.3 error_type 映射（拖放专用）

拖放活动的错误不是"选错干扰项"，而是过程行为。预定义集合：

| error_type | 含义 | 适用 mode |
|------------|------|-----------|
| `order_local_swap` | 仅相邻两项顺序颠倒 | sort |
| `order_reversed` | 整体反序（升降序理解反了） | sort |
| `attr_confusion` | 按错误属性配对/分类（如按颜色而非大小） | match group |
| `boundary_miss` | 中间档判断失误，两端正确 | sort match group |
| `insufficient_resource` | 选了不够用的资源 | fit |
| `suboptimal_choice` | 可行但非最优（不计错，仅记录） | fit |
| `none` | 一次成功 | 全部 |

### 8.4 过程数据必填

拖放活动不以"对错"为主要信号——四个 Runtime 都让孩子改到做对为止。
因此 `process` 必须记录：拖动次数、纠正次数、以及该 mode 的关键中间量。
只记录最终 `result` 视为不合格。

### 8.5 反馈非惩罚原则

放错必须可恢复：抖动/退回/提示，不清空全局进度、不结束活动、不倒计时。
复位按钮只清摆放状态，**不清零过程计数器**。

## 9. 变更管理

任何题型规则修改必须同步更新：

1. 本文档对应条目。
2. 该模块设计说明（如 Size Pattern 设计文档）。
3. 数据版本说明与变更记录。
