# Pattern 模块出题与质量门禁规范

## 版本

- v1.3.0 (2026-09-04) — 新增 §2.1 学习系列规律模块的三维附加必填项（结构 × 载体 × 任务 + 矩阵格）
- v1.2.0 (2026-08-16) — 新增 §9 Mini-game（限时连续小游戏）门禁；原 §9 变更管理顺延为 §10
- v1.1.0 (2026-08-12) — 新增 §8 Interaction（拖放活动）门禁
- v1.0.0 (2026-07-03)
- 适用范围：所有 Pattern 系列（Number / Color / Visual / Temporal / Motion / Size）
  与 Learning 系列的 Puzzle / Interaction / Mini-game 活动

## 1. 目标

本规范用于保证 Pattern 模块在扩展时：

1. 题型边界清晰，可解释且可复核。
2. 干扰项设计一致，错误归因稳定。
3. 数据记录结构统一，可横向比较。
4. 不因题目漂移导致能力标签失真。

## 2. 题型规格必须先行（先规格后实现）

每个新题型上线前必须有题型规格单（见附录 A），至少覆盖：

1. pattern_type
2. ability_tag
3. 允许变量
4. 禁止变量
5. 序列长度
6. 干扰项模板
7. error_type 映射规则
8. 边界策略
9. 示例题与反例题

未完成规格单，不得进入开发。

### 2.1 学习系列规律模块的附加必填项（v1.3.0 起）

学习系列的规律单元用三维模型出题（结构 × 载体 × 任务，见
`docs/patterns/PATTERN-MODULE-ARCHITECTURE.md`），所以上面第 1 项
`pattern_type` 对它不够用。该模块的每份规格单必须额外写明：

1. `structure` —— `pattern.json → typeTree` 的 7 个 id 之一；
2. `carrier` —— `pattern.json → carriers` 的 id，且其 `status` 不得为 `reserved`；
3. `task` —— `pattern.json → taskTypes` 的 6 个 id 之一；
4. **矩阵格与 `levelFloor`** —— `(structure, task)` 必须是
   `pattern.json → taskMatrix` 里的允许格，且规格单声明的等级不低于该格的 `levelFloor`；
5. 上报的**根基因**，按「结构基因 + 规则真正变化的载体基因」推出，不得自行增减。

第 4 项是硬门禁：落在 `taskMatrixExclusions` 里的组合（如 `numerical × match`）
连规格单都不许写。要新增组合，先改矩阵并在 `taskMatrixExclusions` 里删掉对应理由，
`metadata/validate.html` 的 S7 会同时核对两边。

## 3. 通用质量门禁

### 3.1 单变量原则

单题只允许一个主变量发生变化。若同时变化多个变量，必须拆成独立题型。

### 3.2 可辨识性原则

关键差异必须肉眼可分辨，不允许边界模糊导致多解。

### 3.3 无歧义原则

题目应保证唯一最优答案，且干扰项有明确错误语义。

### 3.4 边界显式原则

越界规则（如最大值后行为）必须在规格单明示，不得隐式处理。

### 3.5 可归因原则

每个错误选项必须可映射到明确 error_type。

## 4. 干扰项与错误类型规范

每题 4 个选项建议结构：

1. correct
2. pattern_misread（规律误读）
3. adjacent_item（相邻项误判）
4. random 或 extreme_out_of_range

循环题可替换为 cycle_misalign。

error_type 命名必须统一使用小写蛇形（snake_case），禁止同义重复命名。

## 5. 数据记录规范

推荐单题记录字段：

```json
{
  "module": "size_pattern",
  "pattern_type": "grow",
  "level": 1,
  "correct": true,
  "time_ms": 3500,
  "error_type": "none"
}
```

要求：

1. module 与 pattern_type 必填。
2. time_ms 使用毫秒整数。
3. error_type 来自预定义集合。
4. ability_tag 映射规则在模块级文档中固定。

## 6. Size Pattern 专项边界（首版固定）

1. 只做纯视觉大小感知。
2. 禁止数字、单位、百分比、倍数计算。
3. 固定离散档位（3-4 档）。
4. 统一基线对齐，避免位置线索干扰。
5. 同题固定同一图形，仅改变整体大小。
6. 首版不做动画，不做二维长宽比变化。

## 7. 上线前最小测试集

### 7.1 出题校验

1. 100 道随机题无越界。
2. 所有题 answer 均包含在 options 内。
3. 所有 options 可映射到已定义 optionTypes。
4. 无重复选项、无空值选项。

> 第 2–4 条只适用于选择题。拖放类活动没有 options，**不得**套用这三条
> （否则合法活动会被判为不合格），改按 §8 校验。

### 7.2 渲染校验

1. 问号占位统一为 '?'.
2. 序列与选项在移动端可完整显示。
3. 基线对齐策略在各屏宽下一致。

### 7.3 统计校验

1. 正误计数正确。
2. error_type 统计与作答结果一致。
3. 历史记录写入与读取正常。

## 8. Interaction（拖放活动）门禁

参考实现：`docs/patterns/COMPARISON-INTERACTION-IMPLEMENTATION.md`

### 8.1 结构合法性（替代"answer 在 options 内"）

拖放活动的"正确答案"是一个映射或顺序，不是一个选项。上线前必须逐 mode 校验：

| mode | 必须成立 |
|------|----------|
| sort | 目标顺序与元素一一对应、严格单调、相邻差值 ≥ 规格单声明的最小可辨识差 |
| match | 左右等量、每个待配对项**恰好**有一个正确目标、映射一对一 |
| group | 物品总数 = 分组数 × 每组数、每组期望数量正确、组标识合法 |
| fit | 恰好一个明确的不合格项、正确项确实可用、正确项是最优解（最小的可用项） |

通用要求：元素 id 唯一、渲染所需字段（尺寸/颜色/emoji）齐全、
每次生成的布局指纹去重率 ≥ 50%。

### 8.2 唯一最优解原则

§3.3 无歧义原则在拖放活动里的含义是：**允许多个可行解，但必须有唯一最优解，
且非最优解必须给出区别于错误的反馈。**

以 Fit（搭桥）为例：任何长度足够的木板都能过河，所以都算完成；
但「刚好」与「过长」必须给不同文案（`optimal` 字段区分），
绝不允许把可行解报成失败，更不允许用错误的原因描述（如把过长的板说成"太短"）。

### 8.3 error_type 映射（拖放专用）

拖放活动的错误不是"选错干扰项"，而是过程行为。预定义集合：

| error_type | 含义 | 适用 mode |
|------------|------|-----------|
| `order_local_swap` | 仅相邻两项顺序颠倒 | sort |
| `order_reversed` | 整体反序（升降序理解反了） | sort |
| `attr_confusion` | 按错误属性配对/分类（如按颜色而非大小） | match group |
| `boundary_miss` | 中间档判断失误，两端正确 | sort match group |
| `insufficient_resource` | 选了不够用的资源 | fit |
| `suboptimal_choice` | 可行但非最优（不计错，仅记录） | fit |
| `none` | 一次成功 | 全部 |

### 8.4 过程数据必填

拖放活动不以"对错"为主要信号——四个 Runtime 都让孩子改到做对为止。
因此 `process` 必须记录：拖动次数、纠正次数、以及该 mode 的关键中间量。
只记录最终 `result` 视为不合格。

### 8.5 反馈非惩罚原则

放错必须可恢复：抖动/退回/提示，不清空全局进度、不结束活动、不倒计时。
复位按钮只清摆放状态，**不清零过程计数器**。

## 9. Mini-game（限时连续小游戏）门禁

参考实现：`docs/patterns/COMPARISON-MINIGAME-IMPLEMENTATION.md`

Mini-game 与前两类的根本差别是**时间进入了题目**。时间一旦介入，
所有"慢"的孩子都可能被系统误判为"不会"，因此本节的门禁大半是保护条款，
不是玩法条款。

### 9.1 计时的红线（不可协商）

1. **单个 round 不得有时限。** 反应慢**绝不**判错。
   整局时间到就结束整局，未作答的那个 round **丢弃**（不计对、不计错）。
2. **必须可暂停**，且失去可见性（切标签/切后台/窗口失焦）时**自动暂停**。
   恢复必须是显式点击，不得自动恢复。
3. **暂停时长必须从 `responseMs` 中扣除**，否则一次接电话就会污染时间数据。
4. **开局必须有一次显式的"开始"点击**（准备页），不允许活动一挂载就开始计时。
5. **K1/K2 不得使用倒计时呈现。** 同一段时间必须画成"收集进度条"（越玩越满），
   而不是"剩余时间"（越玩越少）。倒计时对幼儿是压力源，从 G1 起才允许。

### 9.2 不惩罚原则（承接 §8.5）

1. 答错只给即时反馈，**不扣时间、不扣进度、不结束整局**。
2. **准确率低于阈值判为 `completed`，不判 `failed`。** 模板照样计为已完成，
   Cycle 永远不能因为一个难游戏卡住不推进。
3. **中途退出不得记录为失败。** 不生成 Attempt，模板留在池里下次再出；
   `aborted` 只作本地遥测。
4. **UI 不得显示数字分数。** 分数一露出就变成目标，孩子会用手速换准确率。
   低龄用星星、高年级用连对；原始分只存 `process.score` 供分析。

### 9.3 有效性下限（防止把游戏记成能力）

| 门禁 | 要求 | 理由 |
|------|------|------|
| 最小 round 数 | `rounds >= max(3, ⌈roundTarget × 0.5⌉)` 才允许判 `passed` | 打了两下就通过说明不了任何事 |
| 每 round 可用时间 | `durationSec / roundTarget >= 1.5s` | 低于此值考的是反射，不是比较 |
| 误触上限 | 判定区域间距足够，且相邻两次点击的最小间隔不得判为有效两次作答 | 连点会刷出假的高准确率 |
| 精细动作污染 | 需要精确瞄准/追打移动目标的玩法**不得**用于 K1 | 测到的是手，不是脑 |

### 9.4 出题结构合法性（替代"answer 在 options 内"）

Mini-game 的一局包含 N 个 round，**必须整局预生成**（不得边玩边生成），
以便离线逐 round 校验、可复现、并能强制配平答案。上线前必须校验：

1. `rounds.length === params.roundTarget`；每个 `roundIndex` 等于其下标。
2. 每个 round 的关键数值成对存在、为数字、且**不相等**（无歧义原则）。
3. **答案必须从数值重新推导**，不采信生成器自报的 `answer`——
   这是唯一能抓住镜像/翻转 bug 的办法。
4. **答案侧配平**：整局 `|左答案数 − 右答案数| <= 1`。
   限时游戏特有的作弊路径是"连点同一边"；不配平就等于教会孩子偷懒。
5. 极性（问"更大"还是"更小"）必须归一到**单个布尔字段**，
   不允许每个维度各用一个名字。
6. `durationSec` / `roundTarget` / `passThreshold` / `timerStyle` 必须全部带钳制，
   坏模板不得造出畸形局。

### 9.5 分层强制（框架不许被绕过）

1. **Runtime 只负责生命周期，Adapter 只负责玩法。**
   若新增游戏需要修改 Runtime，先判定这是不是玩法逻辑漏进了生命周期层。
2. **Adapter 不得结束整局、不得写 Attempt、不得接触 Cycle**，
   只能"申请"结束（`requestFinish(reason)`）。
3. **Mini-game 不得直接操作 Cycle。** Runtime 交出 Attempt，由上层交给 Cycle。
4. **一个 Mini-game Template 只算 Cycle 中一个模板。**
   N 个 round 必须汇总为一个 Attempt，不得放大为 N 个 Attempt。

### 9.6 过程数据必填（承接 §8.4）

`process` 至少必须包含：`engine`、`rounds`、`correctRounds`、`wrongRounds`、
`accuracyPct`、`bestStreak`、`avgRoundMs`、`endReason`、`timedOut`、
`minRoundsMet`、`topErrorType`。

**`responseMs` 在 Mini-game 里是整局净时长，与 Puzzle 的单题时长不可比。**
后端聚合任何时间指标必须按 `game_mode` 分桶；Mini-game 的可比指标是
`process.avgRoundMs`。

### 9.7 error_type 映射（Mini-game 专用）

| error_type | 含义 |
|------------|------|
| `perception` | 正向提问下答错——看错了 |
| `polarity_confusion` | 反向提问下答错——把"更小"听成"更大" |
| `none` | 无错 |

`perception` 与 `polarity_confusion` 的教学含义完全不同，
**不得**统一记为"答错"。

### 9.8 上线检查清单

1. 语法检查全通过。
2. 出题校验（每模板 ≥ 20 次随机生成）FAIL 0，含 §9.4 全部 6 条。
3. 生命周期端到端用例通过，**至少覆盖**：干净一局、低于阈值、超时（0 作答）、
   反馈期间暂停、中途退出。
4. Attempt 管道用例通过（`mode` / `result` / `process` 落库正确）。
5. 真机手动跑完整一局。

> 第 3 条的"反馈期间暂停"是实测踩过的坑：暂停若发生在答题反馈的那几百毫秒内，
> 待执行的"下一个 round"回调会被丢弃，整局卡死。**任何新 Runtime 改动都必须回归这条。**

## 10. 变更管理

任何题型规则修改必须同步更新：

1. 本文档对应条目。
2. 该模块设计说明（如 Size Pattern 设计文档）。
3. 数据版本说明与变更记录。
